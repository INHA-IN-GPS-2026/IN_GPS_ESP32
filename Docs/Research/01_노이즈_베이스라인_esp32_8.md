## 3. 어떤 노이즈인가 — 공통모드가 지배

두 써미스터는 물리적으로 별개 부품·별개 ADC 채널이므로, 노이즈가 순수
SAR 변환 노이즈(채널 독립)라면 잔차 상관 ≈ 0이어야 한다. 실측:

- **temp1↔temp2 잔차 상관 = 0.67** (원시 0.76)
- 분산 분해(직교): 총 0.273℃ = **공통모드 0.218℃ ⊕ 채널독립 0.163℃**

즉 노이즈의 약 2/3(분산 기준 64%)는 두 채널이 **동시에** 겪는 교란 —
전원 레일/Vref 리플, BLE TX 버스트 전류에 의한 그라운드 바운스 등 —
이고, 채널 고유의 SAR 변환 노이즈는 0.16℃(≈7.6 LSB) 수준이다.

이는 Espressif 공식 문서의 서술과 정합한다: ESP32-S3 ADC는 노이즈에
민감하며 **입력 패드에 100nF 바이패스 캡 + 멀티샘플링**을 권고
([ADC Calibration Driver, "Minimize Noise"](https://docs.espressif.com/projects/esp-idf/en/latest/esp32s3/api-reference/peripherals/adc/adc_calibration.html)).

### 오버샘플링이 0.08℃에서 멈춘 이유 (이전 실측의 사후 해명)

백색 노이즈만이라면 200샘플 평균 후 σ = 0.273/√200 = **0.019℃**여야 하는데
이전 실측은 **0.08℃**였다. 이 차이가 바로 공통모드 성분이다 — √N 저감은
비상관 성분에만 유효하고, BLE 버스트 같은 상관 노이즈는 1초 창 안에서
평균으로 지워지지 않는다. 측정된 공통모드 0.218℃의 상당 부분이 1초 창
내 저주파로 남는다고 보면 0.08℃ 잔존이 설명된다.

### 3-1. 왜 temp1 ≠ temp2 인가 (같은 온도인데 두 채널 값이 다른 이유)

두 써미스터(TH1=GPIO3=CH2, TH2=GPIO4=CH3)는 같은 실온에 있는데도 순간값이
어긋난다. 두 종류의 오차를 분리해야 한다.

**(a) 평균은 사실상 일치 — 계통 오프셋 없음.**
temp1-temp2 **평균 = +0.006 ℃**. 한쪽이 지속적으로 높다는 편향은 없다.
즉 이번 개체는 부품 공차가 우연히 잘 상쇄됐다.

**(b) 순간값 차이 — 채널 독립 랜덤 노이즈가 원인 (현재 지배적).**
차이 d=temp1-temp2의 **σ = 0.231 ℃**. 두 채널이 독립이면 σ_diff = √2·σ_indep
이므로 **채널당 독립 노이즈 σ = 0.231/√2 = 0.163 ℃** — §3의 분산분해 독립성분
0.16℃와 정확히 일치. 원인:

- ULP가 CH2를 읽고 **그 다음** CH3를 읽음(동시 아님, 순차). 두 읽기 사이 수십 µs
  동안 공통모드(전원/Vref/BLE 버스트) 위상이 이동 → 같은 교란도 두 채널에서
  다른 값으로 잡혀 차이에 남는다.
- 각 채널 고유의 SAR 변환 노이즈·양자화·S/H 정착 오차(1샘플이라 그대로 노출).
- 실리콘 채널간 INL/DNL·오프셋·게인 미스매치.

**(c) 계통 오프셋이 커질 수 있는 요인(이번엔 상쇄됨, 일반적으론 주의).**
부품이 물리적으로 2개 → R25 ±1 %(±0.24℃), B ±1 %, 분압저항 ±1 %(±0.24℃),
PCB 위치 차이에 의한 실제 열구배, 자기발열 차이. 다른 보드에선 오프셋이
±0.2~0.3℃까지 벌어질 수 있다.

**처방:** temp1≠temp2의 현재 원인은 거의 전부 (b) 독립 노이즈이므로
**오버샘플링(√N)이 직접 해결**한다 — 독립성분 0.163℃는 200샘플 평균 시
0.163/√200 ≈ 0.012℃로 소멸, 두 채널이 훨씬 잘 겹친다. 반면 (c) 계통 오프셋은
평균으로 못 지우고 센서별 실측 S-H 계수라야 흡수된다(→ `Reference/NTC_Beta_vs_SteinhartHart.md` §7).

→ **결론: 다음 단계 개선은 소프트웨어(√N)가 아니라 하드웨어 경로**
(100nF 바이패스, ADXL/NTC 레일 디커플링, 필요시 아날로그 레일 분리)와
**adc_cali 적용**이어야 한다. 근거: [ESP32-S3 HW Design Guidelines](https://docs.espressif.com/projects/esp-hardware-design-guidelines/en/latest/esp32s3/esp-hardware-design-guidelines-en-master-esp32s3.pdf).

## 4. 정확도(계통오차) 버짓 — 데이터시트 공차 vs 현재 코드

기준: 배포용 A~C = EPCOS B57541G1103**F000**(특성 **8307**, B25/85=3478·B25/100=3492, ±1%),
분압 10kΩ, `sensor.c`의 고정 3300mV 가정. 각 요인 단독 오차:

| 요인 (데이터시트/사양 공차) | @20℃ | @40℃(경보대역) |
|---|---|---|
| NTC R25 ±1 % (F 공차) | ∓0.24 ℃ | ∓0.27 ℃ |
| NTC B ±1 % | ∓0.05 ℃ | ±0.16 ℃ |
| 분압저항 ±1 % | ±0.24 ℃ | ±0.27 ℃ |
| **ADC 스케일 ±5 %** (Vref 편차 소폭) | **±2.2 ℃** | **±3.7~3.9 ℃** |
| **ADC 스케일 ±9 %** (Vref 1100±100mV 최악) | **±3.9 ℃** | **−6.5~+7.2 ℃** |
| 랜덤 노이즈 (본 측정, 1샘플) | σ 0.27 ℃ | σ ~0.3 ℃ |

**지배 항은 압도적으로 ADC 스케일 오차**다. 현재 raw→mV 변환이 eFuse
캘리브레이션(adc_cali) 없이 3300/4095 고정 스케일이기 때문. 부품 공차
(±1 %)는 다 합쳐도 ±0.5℃ 수준인데 ADC 경로가 최대 ±7℃를 만들 수 있다.
Vref 1000~1200mV 편차와 adc_cali 근거: [ADC Calibration Driver](https://docs.espressif.com/projects/esp-idf/en/latest/esp32s3/api-reference/peripherals/adc/adc_calibration.html).

단, ULP 경로는 adc_cali API를 못 쓰므로 실전 해법은 **센서별 실측 3점
S-H 계수가 ADC 스케일 오차까지 통째로 흡수**하게 하는 것
(→ `Reference/NTC_Beta_vs_SteinhartHart.md` §7: 10k 그룹 오차 56~60% 감소 실증).

## 5. 결론 및 다음 단계

1. **베이스라인 확정**: 1샘플 σ=0.27℃(12.7 LSB), 백색 + 공통모드 2:1 혼합.
2. **노이즈 정체**: 채널독립 SAR 노이즈 0.16℃ + 공통모드(전원/Vref/RF) 0.22℃.
   Espressif 권고(100nF+멀티샘플링)와 정합.
3. **오버샘플링 복원**(ULP `sum_ntc` 소비 코드)으로 0.08℃까지는 소프트웨어로 도달
   가능(√N, 기실증). 그 밑은 HW 대책 필요.
4. **정확도는 노이즈보다 ADC 스케일이 문제** — 실측 3점 S-H 캘리브레이션으로 흡수
   (§7-4 프로토콜: 열평형 + 기준계 실측값).
5. 재실험 시 이 캡처와 동일 조건으로 A/B 비교: ①현재(1샘플) → ②오버샘플링
   → ③오버샘플링+S-H. 각 단계의 σ와 기준계 대비 오차를 이 폴더에 축적.
